# Real-Time Face Detection

Containerized backend + frontend for video face detection. A user uploads a video, the backend detects the (single) face in each frame, persists per-frame ROI data, draws an axis-aligned bounding box on every frame, and serves both the annotated video and the ROI data through a small JSON API. The frontend is a React app that uploads the video and renders the result.

Face detection uses [`face_recognition`](https://github.com/ageitgey/face_recognition) (dlib). **OpenCV is not used anywhere** — frame I/O is done with `imageio` / `ffmpeg` and rectangles are drawn with Pillow.

## Status

It is end-to-end and tested. React frontend uploads a clip, the API runs the detection pipeline, and the UI renders the annotated video alongside the per-frame ROI table. `pytest` covers validation, error paths, and the happy path with a generated fixture clip.

## Quick start (Docker)

```bash
docker build -t face-detection .
docker run --rm -p 5000:5000 -v "$(pwd)/data:/app/data" face-detection
```

Then open <http://localhost:5000>.

The first build is slow (~3–5 min) because dlib compiles from source. Subsequent builds are cached.

## API

| Method | Path                    | Description                                            |
| ------ | ----------------------- | ------------------------------------------------------ |
| POST   | `/api/videos`           | Upload a video (mp4 / webm / mov). Detection runs synchronously in the request. Returns `201` with the video record and a `Location` header. |
| GET    | `/api/videos/{id}`      | Streams the processed mp4 with bounding boxes drawn. Supports HTTP Range requests so `<video>` seeking works. |
| GET    | `/api/videos/{id}/rois` | JSON: `{video_id, status, fps, frame_count, width, height, rois: [{frame, t_ms, x, y, w, h}, ...]}`. |

Status codes the API can return: `201` upload + processed, `400` missing/invalid file, `404` unknown video, `409` upload accepted but processing is still in flight (only reachable in concurrent setups), `413` payload too large, `415` wrong mimetype/extension, `422` source video could not be processed (corrupt / unreadable / no frames), `500` unexpected. Errors are JSON: `{"error": {"code", "message"}}`.

Upload limits and allowed formats are configurable through environment variables — see `.env.example`.

### Try it

```bash
curl -i -F "video=@sample.mp4;type=video/mp4" http://localhost:5000/api/videos
curl -O -J http://localhost:5000/api/videos/1
curl -s http://localhost:5000/api/videos/1/rois | jq '.rois | length'
```

### Design trade-off: synchronous processing

`POST /api/videos` blocks until the detection pipeline has finished, so the response can take a while on long clips. This is deliberate — pulling in a job queue (Celery + Redis, RQ, etc.) wasn't worth the complexity for this scope. The gunicorn timeout in the Dockerfile is set to 300 s; combined with the `MAX_UPLOAD_MB=50` cap that's plenty of headroom for typical clips.

See [`docs/architecture.png`](docs/architecture.png) for the system diagram. The diagram is generated by [`docs/diagram.py`](docs/diagram.py) and is regeneratable.

## Local development

Backend:

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt   # runtime + pytest
python wsgi.py
```

Frontend:

```bash
cd frontend
npm install
npm run dev
```

The Vite dev server proxies `/api/*` to `http://localhost:5000`.

## Tests

```bash
cd backend
pip install -r requirements-dev.txt
pytest
```

The test suite (16 tests, ~0.5 s) covers:

- **Validation paths**: missing file, blank filename, disallowed extension, disallowed mimetype, oversized payload (`413`), unprocessable source video (`422`).
- **HTTP semantics**: `404` for unknown video, `405` for wrong method, `Location` header on `201`.
- **Happy path** (full upload → process → fetch): generates a 5-frame fixture clip with `imageio`, monkey-patches `detect_face_box` so the suite doesn't need dlib, then asserts persisted ROIs, served mp4, and metadata.
- **Renderer correctness**: outline drawn at corners, interior left untouched, frame not mutated in place.

`face_recognition` is imported lazily inside `detect_face_box`, so `pytest` runs cleanly without installing dlib.

## Limitations (intentional)

These were left out to keep the scope honest — each one is a deliberate
"don't" rather than something missed:

- **No background job queue.** Processing is synchronous inside `POST /api/videos`. A job runner would be the right next step for longer clips.
- **No auth.** Out of scope for this exercise.
- **No migrations tool.** SQLite + `db.create_all()` is enough at this size; switching to Postgres would mean adding Alembic.
- **No CI config.** Tests are designed to run locally with a single `pytest`.

## Troubleshooting

- **`docker build` is slow the first time.** dlib compiles from source as part of the `face_recognition` install (~3–5 min). Subsequent builds reuse the layer.
- **`<video>` won't seek in the browser.** Make sure the response actually has `Accept-Ranges: bytes`. Flask's `send_file(..., conditional=True)` enables this; reverse-proxies sometimes strip it.
- **413 on a file under 50 MB.** Check that `MAX_UPLOAD_MB` in your environment hasn't been overridden lower.
